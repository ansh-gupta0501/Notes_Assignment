# Amazon Route 53 Overview

- This service is used to deploy a global application.
- Route 53 is a managed **DNS** or **Doman Name System.**
- DNS is just like a phone book , it's a **collection of rules and records**, which help clients understand how to reach a server through URLs.

- In AWS , the most common records are:
    - say you are mapping www.google.com to an IPv4 address. Then this is called an A record
    **www.google.com => 12.34.56.78 == A record (IPv4)**
    - If you are mapping www.google.com to a long IPv6 address , it's called the quadruple A record.
    **www.google.com => 2001:0db8:85a3:0000:0000:8a2e:0370:7334 == AAAA IPv6**
    - If you map a host name to another host name, search.google.com into the previous address, is called a CNAME because we're mapping a host name to host name
    **search.google.com => www.google.com == CNAME : hostname to hostname**
    - If you're mapping a host name into an AWS resource, it's a special type of record called an Alias record
    **example.com => AWS resource == Alias (eg. ELB, CloudFront, S3, RDS etc...)**


# Route 53 - Diagram for A record
- Say we want to see what happens for an A record
- We have Web browser and we have an Application server that we've deployed that has a public IPv4
- Now we want to be able to access our application server using a normal URL, so for this we're going to go into Route 53 and we're going to create **A Record** so that when the web browser does a DNS request for myapp.mydomain.com, then the DNS will reploy back with an ip. And then that IP can be used by our Web Browser to get to our Correct server and then get the HTTP response from our server. This is the basics of how a DNS work at very very high level 
```
                      Route 53
                      ^   |
                      |   |
 DNS request          /   / Send back IP : 32.45.67.85
 myapp.mydomain.com  /   /  (A record : hostname to IP)
                    /   /
                   /   /
                  /    v      HTTP Request IP:32.45.67.85, Host: myapp.mydomain.com
               Web Browser  --------------------------------------------------------------> Application Server (hosted say on EC2 instance)
                            <--------------------------------------------------------------                                            
                                            HTTP Response


```

# Route 53 Routing Policies
- The first one is called a **Simple Routing Policy** which as **No health checks**. So our Web browser will go into our DNS system(Route 53), does a DNS query and gets an IPv4 ,for example, as a result , this is a **simple Routing Policy**

```

Simple Routing Policy (No health checks)

               foo.example.com
            ----------------------->
web browser                            Route 53
            <----------------------
            A: 11.22.33.44
```

- Next we have **Weighted Routing Policy**. It allows us to distribute the traffic across multiple EC2 instances. So , example, we have to assign weights to our EC2 instances, for example 70 , 20 and 10 , and then our DNS will  make sure that our clients have 70% of the traffic onto the first one, 20% of the traffic onto the second one and 10% of the traffic on to the third one. This is effectively some kind of load balancing. So in this Weighted Routing Policy we can use health checks

```

Weighted Routing Policy 

                    70%
            ----------------------->  EC2 Instance (weight 70)
Route 53            20%                
            ----------------------->  EC2 Instance (weight 20)
                    10%
            ----------------------->  EC2 Instance (weight 10)
```

- Next , we have **Latency Routing Policy**. In this example, say we are displaying our application globally. One in California and other one in Australia. And our users are all around the world. The Latency Ruting Policy will look at where the user is located and if they're located close to California , then they will be redirected to talk to that server. And if they are close to Australia , then they will be redirected to talk to Australia server. And this is based on the latency.
    - So in this case , Route 53 will be used to minimize the latency between the users and the servers by making the users connect to the server that is closed to them.

- Finally , we have a **Failover Routing Policy** in which we have a client and we have a primary EC2 instance and a Failover one. And so our DNS system will do health check on the primary and in case the primary instance fails , then we will be redirected to the failovers . This helps with disaster recovery . 

- So the client will know exactly which instance to connect to based on the health of that instance. 

```
    Failover routing policy 
    
                            Primary EC2 instance
                               /
            Health check on   /
              Primary        /
                            /
    client ---------> Route 53
                            \
                             \ 
                              \ Failover Ec2 instance.   

```
